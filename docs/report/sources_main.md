# Source keys of the main text (report v2)

The main text of report v2 (the title block to the References) carries no HTML comments, so that the outline's word rule, whitespace tokens from the line after `## Abstract` to the line before `## References`, counts only what the PDF shows. This file holds the source keys of its numbers instead: one entry per paragraph, table or list, under the main-text section it belongs to, with the opening words of each block it covers. Most entries are the comments of the assembled main text of 2026-10-14, re-anchored where one comment covered several paragraphs; §7 and the conduct section were rewritten at the final assembly and keyed then.

On 2026-10-20 the main text was cut to the competition's 8 pages of the NeurIPS template, and this file was re-keyed to the cut text. Blocks that left the main text took their keys with them as `<!-- src: ... -->` comments at their new places: the title-block note (App H.1, "Convention, in brief"), §4.3's gate, scale and Figure 1 (App C.4, now Figure C1), §5.2's regression test, line-read display and ablation (App B.1, "Inference"), §5.3's two C1m sentences of design section 11 (App G.6, "The pool evaluation"), §6.4's Table 4 and its last sentences (App F.1, Table F.1a) and §7's Table 5 (App C.6, Table C.6a). §2.3 is now two sentences of §2.2, §4.4 one sentence of §4.3, and Tables 2 and 3 are one table, Table 2. Section 8 is "Limitations".

Later on 2026-10-20 (fix-1) the verified issues of the four checks of the cut were applied: §1 and §2 lost their subsection headings (§1.1 to §1.4 and §2.1 and §2.2 are run-in paragraphs, cited as §1 and §2), Table 1 follows §6.1's first paragraph, §1's oracle sentence (0.25, 0.176, 0.0433) moved to App A.1 with its key, the six-point-eight and five-point-four pair-SE gaps of §6.1 stay in App D.7, and the keys below were corrected where the checks found them imprecise (§4.3's 0.46, §6.4's subject-side SE and 0.063, §8's run-level sd).

Conventions. A key is a committed file and a key path in it; braces list sibling keys, `<R>` stands for each regime and `<C>` for each pool candidate (C1, C1m, C2), and a value in parentheses after a key is the stored value or a note on it. F§ is a section title of `docs/findings.md`, P§ a section of `docs/protocol.md`; "report v1.0.1" is the previous report, `docs/report/draft.md` at git tag `v1.0.1`; "derived" marks a number computed from stored values (App H.1); "carried" marks a number the main text keeps from the appendix it names, where its key is. Numbers that the text sources inline (F§, P§, a named file or an appendix) need no entry here. No entry holds item text, an anonymous hidden-benchmark id or anything keyed on one.
